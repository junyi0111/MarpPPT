# MarpPPT 品質基準

這份基準用來比較版本變更前後的簡報品質與工作量。輸入只使用公開、合成的測試素材，不包含使用者的 DeepSeek 文件或對話附件。

目前基準版本是 `3ae3597`。案例清單、預期頁數、必留事實和評分規則在 [quality manifest](../../tests/fixtures/quality/manifest.json)。

## 基準狀態

| 項目 | 現況 | 證據／限制 |
| --- | --- | --- |
| 公開案例描述與評分規則 | available | manifest 已固定案例 ID、權重、1／3／5 分描述 |
| 八組正向情境 | partial | 4 組使用現有合法八頁 fixture；4 組標為 `fixture-pending`，不重複使用不相符輸入冒充結果 |
| 修改前 PPTX／Marp／縮圖 | not_run | 目前套件沒有獨立的公開基準產生器；現有 e2e fixture 可在本機產生候選，尚未保存為發布基準 |
| PowerPoint 開啟、另存、關閉、重開 | not_run | 這份基準沒有宣稱宿主端已驗證 |
| 模型 token／費用 | unknown | 宿主未提供可追溯的 token 計數；不能由本機時間換算 |
| 人工修正頁數 | unknown | 尚未完成統一的人工評分流程 |

## 評分方式

每份成品用五個維度評分：內容／證據 30%、層次／焦點 25%、可讀性／留白 20%、編輯便利 15%、可及性 10%。每項使用 1、3、5 分錨點，中間分數可用但要寫理由。發布候選的加權總分至少 80/100，且每個維度至少 3/5。

評分者必須保存正面與問題頁面的 slide ID、問題描述及使用的證據。縮圖檢查只能判斷整份故事與焦點；文字是否能在投影後閱讀，仍要記錄投影設備或人工放大檢查。

## 產出規則

每個已標為 `available` 的案例都要使用同一個基準提交、相同主題設定和相同預覽工具產生候選。產物保存於本機未追蹤的品質工作目錄，公開倉庫只保存輸入、manifest、評分規則和匿名摘要，不提交輸出中的個人路徑或暫存檔。

若案例輸入與預期頁數不一致，狀態必須是 `fixture-pending`，不能把現有產物當成該案例的基準。若 PowerPoint、CUA、字型或預覽器不可用，對應檢查寫成 `not_run` 或 `partial`；CI 通過不能替代這些宿主檢查。

下一個 P0 工作是把基準產生器和發布套件入口固定下來，之後再為 `fixture-pending` 案例補上真正的固定來源與計畫。
